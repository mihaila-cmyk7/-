# Шахматы на троих

Игра на 96 клетках для трёх игроков: три армии по 16 фигур, три короля, один
победитель. Работает как обычный статический сайт — сервер не нужен.

![Доска «Звезда»](docs/live-star.png)

## Что внутри

| Режим | Нужен сервер? |
| --- | --- |
| **Игра с ботами** — один на один против двух ИИ | нет, всё в браузере |
| **Втроём на одном телефоне** — по очереди, без сети | нет |
| Онлайн-столы по коду/ссылке | да, серверная часть (см. ниже) |

Если серверной части нет, приложение само это замечает: в меню остаются
офлайн-режимы и появляется подсказка, а кнопки онлайн-столов скрываются.

## Три доски

В лобби (и ссылкой `?layout=star|ring|trefoil`) выбирается доска — это часть
общей темы стола, её видят все:

- **Трилистник** — три крыла с квадратными клетками и треугольной складкой в центре;
- **Звезда** — ряды идут дугами и сходятся к центру, контур скруглённым треугольником;
- **Кольцо** — дуги с большой ступицей и лучами из центра.

Правила внутри приложения рисуют иллюстрации **для выбранной доски** — из той же
геометрии, что и сама доска.

## Как играть

1. Тап по своей фигуре — появляются точки, куда она может пойти.
2. Тап по точке — ход. Красная рамка означает взятие.
3. Ходят по очереди: белые → красные → чёрные.
4. В центре доска складывается: линии уходят из крыла в крыло (это и есть «шов»).
5. Пешка идёт к центру, переходит шов, превращается на чужом тылу; назад тоже
   умеет — шаг и два взятия в своём крыле.
6. Мат любому королю — победа тому, кто его поставил. Короля нельзя съесть.

## Деплой на GitHub Pages

```bash
git init
git add .
git commit -m "Шахматы на троих"
git branch -M main
git remote add origin https://github.com/<вы>/<репозиторий>.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: GitHub Actions**. Воркфлоу
`.github/workflows/pages.yml` уже лежит в проекте и при каждом пуше в `main`
публикует папку `public/` — сайт откроется на
`https://<вы>.github.io/<репозиторий>/`.

Пути в проекте относительные (`./app.js`), поэтому он работает и в подпапке
репозитория, и на своём домене.

### Локальный просмотр

```bash
node scripts/serve.mjs 8199      # http://127.0.0.1:8199
node scripts/test.mjs            # тесты: 24/24
```

`node_modules` в проекте почти пустой: там только двухфайловая заглушка `sdk`,
нужная тестам серверной части. Ставить зависимости не обязательно.

## Настройки

`public/config.js` — единственное место с настройками:

```js
export const CONFIG = {
  botUsername: '',   // имя вашего бота без @ — нужно только для «Пригласить» в онлайне
  online: 'auto',    // 'auto' | true | false
};
```

`online: 'auto'` включает онлайн только внутри настоящего Telegram-мини-аппа
(проверяется по `initData`). На GitHub Pages он выключен автоматически.

## Онлайн-режим (необязательно)

Онлайн-столы работают на Telegram Serverless: модули в `tgcloud/` (обработчик
команд бота, эндпоинты `createRoom`/`joinRoom`/`roomState`/`roomAction`,
таблица `rooms`, боты и часы на сервере).

1. `tgcloud/handlers/message.js` — подставьте свой `APP_BASE` (адрес печатает `tgcloud push`).
2. `npx tgcloud push` — деплой модулей и папки `public/`.
3. `npx tgcloud webhook sync` — если вебхук разъехался.

Подробности о платформе: [docs/tgcloud-sdk.md](docs/tgcloud-sdk.md),
ориентация по проекту: [AGENTS.md](AGENTS.md).

## Устройство

```
public/            мини-апп (статика, деплоится как есть)
  index.html       разметка экранов: меню, лобби, партия, правила
  app.js           состояние, отрисовка, жесты, лобби, таймеры
  config.js        настройки (бот, онлайн)
  styles.css       базовая вёрстка
  theme.css        палитры доски/фигур/фона, 3D-слой, zen-режим
  calm.css         спокойные переопределения интерфейса
  engine/          board.js (96 клеток, швы), rules.js (ходы, шах, мат),
                   game.js (партия), ai.js (боты), layout.js (три доски)
tgcloud/           серверная часть: schema, lib, handlers, endpoints
test/              24 теста: движок, домен, интерфейс, команды бота
scripts/           serve, shot, test, demo-game, bump-assets, e2e
docs/              скриншоты и справочник по SDK
```

Движок не знает про геометрию доски: соседство, направления и швы живут в
`engine/board.js`, а `engine/layout.js` только рисует. Поэтому одна и та же
партия показывается тремя досками без изменений в правилах.
